# Paper2Lark functional audit

Date: 2026-09-15. Milestone: M3, version 0.4.0 (audited development rebuild).

## Findings and fixes

1. Real Lark template content contains sibling XML elements. The previous parser required a single root and treated the entire template as one protected paragraph. It now accepts XML fragments, preserves list-item text after inline markup, and recognizes the template's explicit Chinese instruction reserving a section for the human reader.
2. Malformed JSON types in reading requests, source inputs, role maps, analysis, note plans, and submission digests could escape validation as Python exceptions. The reproduced cases now return domain errors. Regression cases cover invalid selectors, ownership, variants, depth, reader, source kind, coverage, claims, evidence IDs, note roles, block kinds, and submission hashes.
3. The read skill now explicitly places host-written JSON inputs outside the immutable run directory. The runtime creates the canonical output files during submission; host inputs can use ordinary formatted JSON.

The fixes add no dependency. Original M3 acceptance results remain historical in `compatibility-m3.md`; the build identity below supersedes its runtime hash for this audit.

## Live verification

Using the existing personal profile and Lark credentials:

- Server-verified authentication and existing resource binding succeeded, including 12 field mappings.
- The index export and 45 existing English keyword options were readable. Keyword options satisfied the uniqueness and three-word requirements.
- An existing-paper add preview resolved to the existing record with a no-op; a same-value reading-status update preview also resolved to a no-op.
- Template revision 71 parsed into 87 blocks. A Chinese local draft was generated from an explicitly synthetic text fixture using the live template, and the resulting run passed artifact verification. The reserved question section was protected.
- No Lark data mutation or new OAuth flow was used for this audit. Read-only index acceptance verified the private binding/state tree remained unchanged; draft acceptance deliberately created local run artifacts.

The real template test verifies orchestration and rendering, not the scientific quality of a model review. Real record creation/update was not exercised against the personal index; mutation behavior was exercised by the regression suite's simulated provider.

## Configuration and remaining boundaries

The existing personal configuration resides in a custom private home, not the default `~/.paper2lark`. Supply the existing `--home` and `--profile` values, or equivalent `PAPER2LARK_HOME` and `PAPER2LARK_PROFILE` environment variables. A default-home missing binding is a configuration-selection issue, not evidence that OAuth must be repeated.

M3 ends at local drafts. Wiki note publication, index note-link/summary synchronization, automatic reading-status changes from drafting, and new-library provisioning remain future milestones. The small PDF parser is not an OCR or general-purpose PDF engine. Optional external reader skills, other operating systems, arbitrary custom templates, and semantic evidence accuracy are not certified by this audit. Template protection remains conservative at section boundaries.
