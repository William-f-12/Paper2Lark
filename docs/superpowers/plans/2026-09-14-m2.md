# M2 Collection and Vocabulary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe paper collection, deterministic deduplication, controlled English keywords, paper queries, and explicit index updates for an existing bound Lark library.

**Architecture:** A dependency-free Python core separates pure identity/keyword rules, SQLite identity state, a typed Lark Base adapter, and collection/query/update services. Every mutation revalidates the bound account and live field schema, holds a per-library local lock, uses the current Base vocabulary, and verifies the resulting record before reporting success. Two short host skills translate natural-language intent into versioned JSON request files and call the same packaged runtime.

**Tech Stack:** Python 3.11+ standard library, SQLite, `lark-cli` 1.0.89 compatibility contract, `unittest`, deterministic zipapp packaging.

**Spec:** [Paper2Lark design](../specs/2026-09-13-paper2lark-design.md), sections 4–6, 8, 11–12, M2 gate, and T01–T16.

## Global Constraints

- Project source, documentation, and skill instructions are English; note/library languages remain configurable; keywords are always English.
- Each selected keyword contains at most three words, each paper has at most eight distinct keywords, and live canonical options are reused before new options are created.
- M0 through M2 have no third-party Python dependency and reuse the user's installed `lark-cli` and host model.
- Each generated M2 plugin directory is at most 256 KiB; each workflow `SKILL.md` targets fewer than 500 English words.
- Inputs are data: subprocesses use argument vectors with `shell=False`; paper text, titles, URLs, JSON, and provider hints are never interpreted as shell syntax.
- Writes use the bound user identity, verify the account and schema before mutation, and never start login/logout or silently rebind resources.
- Deduplication reads the full table without applying a filtered view. DOI/arXiv identity and normalized source URLs are authoritative; title similarity never auto-merges records.
- Existing nonempty titles, keywords, status, and priority are preserved by `papers add`; explicit `papers update` is required to change user/workflow fields.
- Local files are never written to the remote source URL field. An exact file hash proves identical bytes only.
- A warning, ignored field, partial page, failed read-back, or ambiguous write result withholds completion.
- The workspace is not a Git repository. Execute in place, preserve unrelated files, and record verification without claiming commits.


- [x] **Step 2: Run service tests and verify red**

Run: `python -m unittest tests.test_papers -v`

Expected: import failure for `paper2lark.papers`.

- [x] **Step 3: Implement deterministic remote candidate resolution**

Build alias indexes from every remote record's canonical paper key and valid source URL. Combine them with the local alias lookup. One matching record is reusable; zero is a create candidate; more than one or disagreeing aliases return `IDENTITY_CONFLICT`. Title is output context only and never enters the merge key.

- [x] **Step 4: Implement preview and apply collection**

Preview returns action `create`, `fill`, or `noop`, the resolved canonical identity, field changes, canonical keywords, vocabulary additions, and `remote_mutations: false`. Apply repeats all reads while holding the per-library lock. It extends live options only when the target record will use them, creates or fills the record, verifies it, then syncs local identity state. Existing nonempty title, keywords, status, and priority survive.

- [x] **Step 5: Implement read-only queries**

Use this query shape:

```json
{
  "schema_version": 1,
  "filters": {
    "record_ids": [],
    "statuses": ["unread"],
    "priorities": [],
    "keywords": ["Transformers"],
    "year_from": 2015,
    "year_to": 2026,
    "text": "attention"
  },
  "limit": 100,
  "include_vocabulary": true
}
```

All filter keys are optional. Filtering is intersection-based except text searches title/authors/venue/summary with case-insensitive containment. Output uses logical field names, canonical status keys where mapped, and a `truncated` flag when `limit` cuts the result.

- [x] **Step 6: Implement explicit updates**

Use this request shape:

```json
{
  "schema_version": 1,
  "record_id": "rec_example",
  "changes": {
    "reading_status": "read",
    "priority": "High",
    "keywords": {
      "selected_existing": ["Transformers"],
      "proposed_new": []
    }
  }
}
```

At least one supported change is required. `reading_status` uses the saved logical status mapping. Priority must match a live option canonically. Keywords are a complete explicit replacement and may be empty. Preview never writes; apply refreshes under the lock and verifies all changed fields.

- [x] **Step 7: Run service and state tests**

Run: `python -m unittest tests.test_papers tests.test_identity_state tests.test_keywords -v`
