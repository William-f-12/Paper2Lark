# Paper2Lark M4 Publication and Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a validated Paper2Lark draft as a verified Lark Wiki note, reconcile its existing Base record, and resume safely after partial or uncertain remote writes.

**Architecture:** Keep the M3 host/model handoff unchanged and add a standard-library-only publishing layer after `drafted`. A publication plan freezes the binding, run artifacts, template state, record preconditions, note payload, and ordered writes. Schema-v3 SQLite state journals note/index operations and verified baselines; the filesystem run manifest exposes progress. New notes and rereads create separate Wiki documents because M0 proved that the tested Lark revision flag is not compare-and-swap.

**Tech Stack:** Python 3 standard library, SQLite, the existing shell-free `lark-cli` runner, `unittest`, deterministic zipapp packaging.

**Spec:** `docs/superpowers/specs/2026-09-13-paper2lark-design.md`

**Implementation status:** Complete. Independent review regressions cover full-content readback, final Base preconditions, stranded-plan adoption, active-run reservation, and completed replay semantics. Final evidence is recorded in `docs/compatibility-m4.md`.

## Global Constraints

- Keep both Claude and Codex packages generated from the same source and below 262,144 bytes each.
- Add no third-party runtime dependency.
- Use the existing authenticated Lark user identity; never start, reset, or revoke authorization.
- `persist_to_library: false` runs remain local-only and cannot be published.
- Never retry an uncertain document creation without first reconciling the intended parent and unique run marker.
- Never replace an existing human-editable note in place; rereads create a separate dated note revision.
- Verify a note before updating Base. Preserve user-changed status/keywords and stop on conflicting managed note-link or summary edits.
- Keywords remain English, contain at most three words each, and total at most eight per paper.
- Keep raw provider output, credentials, resource IDs, and personal library evidence out of public artifacts.
