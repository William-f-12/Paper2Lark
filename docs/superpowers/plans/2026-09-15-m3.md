# M3 Source, Model, and Template Handoff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dependency-free paper-reading handoff that ingests supplied text or text PDFs, records honest coverage, validates model-authored analysis and template roles, and produces a local template-aware draft in both plugin packages.

**Architecture:** Keep model and optional-skill execution in the host. The standard-library runtime owns bounded source ingestion, immutable run artifacts, Lark template snapshots, strict JSON validation, evidence/coverage checks, and deterministic Markdown rendering. M3 stops at a verified local draft; Wiki publication and index-note updates remain M4.

**Tech Stack:** Python 3.11+ standard library, the existing stdlib zipapp and `lark-cli` subprocess adapter, `unittest`, JSON artifacts, SHA-256, atomic filesystem replacement.

**Spec:** `docs/superpowers/specs/2026-09-13-paper2lark-design.md`

## Global Constraints

- Version becomes `0.4.0`; the generated Claude and Codex packages contain byte-identical runtime code.
- No third-party runtime dependency is added. Optional `sci-extract`, `research-paper-review`, and `arxiv2agent` skills remain external.
- Either generated plugin directory stays at or below 1 MiB; every workflow `SKILL.md` stays below 500 English words.
- M3 performs no Wiki note mutation and never marks a paper read.
- Abstract-only input cannot produce a full-reading claim; coverage is explicit in every source, analysis, verification, and draft artifact.
- Private source text, templates, and run artifacts stay under the configured Paper2Lark home and never enter release packages.
- This workspace has no Git metadata, so commit steps are recorded as local checkpoints rather than executed.
