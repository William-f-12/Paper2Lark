# M1 Configuration and Diagnosis Implementation Plan

**Goal:** Provide private cross-host configuration, versioned local state, validated existing-library bindings and read-only diagnostics.

**Architecture:** Shared standard-library Python runtime. Configuration resolves explicit arguments over environment over profile over defaults. A shell-free Lark adapter exposes only read operations in M1. Bindings retain physical resource identities and field IDs. SQLite and atomic local files live outside plugin caches.

**Spec:** [Approved design](../specs/2026-09-13-paper2lark-design.md), sections 3–5, M1 gate, T08–T16.

## Constraints and rulings

- English source and public instructions; configurable Chinese content/library language; English keywords capped at three words/eight labels.
- No automatic `.env` loading, login/logout, remote provisioning or production mutations.
- Diagnose ambiguous `token_missing` as credential availability unknown, not proof of missing login. Verified normal CLI context may establish the distinction.
- Preserve M0's explicit concurrency limitation. Bindings do not authorize later writes.
- Ruling: retain a dependency-free zipapp for M1; no wheel bootstrap is needed without external dependencies. State remains external to either host cache.
- Existing workspace is a greenfield non-Git directory. Work in place; no branch/worktree or commit is implied.

## Tasks and interfaces

- [x] Configuration and state: `config.load_config(home=None, profile=None, overrides=None, environ=None, env_file=None) -> dict`; returned keys `home` (Path), `profile` (str), `settings` (dict). `config.initialize(home)`, `state.initialize(home)`, `state.inspect(home)`; all errors use `errors.Paper2LarkError(code, message)`. Initialization is explicit; inspection creates nothing. Schema v1; fail closed for newer versions; SQLite migration backup and exclusive transaction.
- [x] Lark runner: resolve a native executable; invoke argv with `shell=False`, UTF-8, bounded timeout, no retries, read-operation allowlist. Separate auth-status parsing from normal envelopes; classify errors without leaking raw provider output.
- [x] Bindings: resolve Wiki/Base/template through the CLI, inspect field IDs/types and status options, derive library ID from Base/table, store account fingerprint and schema digest. Atomic persistence; reject account/resource/schema drift. Read-only inspection supports incomplete index schemas.
- [x] Commands and skill: `probe`, `config init/show`, `state init`, `bind`, `doctor`. Doctor never initializes state, resets auth or mutates Lark. Online verification explicitly allows the CLI's ordinary token refresh, not a new login flow.
- [x] Generate both host packages with a version bump; subprocess tests, malformed-input and error-classification tests, live read-only checks and host diagnostic invocation.
- [x] Independent review, fix regression tests, final verification and evidence report.

## Verification

Write failing tests before each component. Use fake CLI executable fixtures only for provider/network/error fault injection; exercise the real runner and local persistence. Live validation reuses existing authentication and reads only. Never claim a mocked provider response proves live API support.

## Outcome

M1 shipped as version 0.2.0. Independent review found unsafe SQLite inspection, incomplete schema validation, an initialization race, malformed provider-response crashes and an explicit-verification edge case. Each defect was reproduced first, fixed and retained as a regression test. Live read-only validation mapped the existing library's 12 fields and left its isolated local binding bytes unchanged during diagnosis. See [the compatibility report](../../compatibility-m1.md).
