# M0 Compatibility Implementation Plan

**Goal:** Build two self-contained plugin artifacts around one deterministic runtime and characterize the installed hosts and Lark CLI.

**Architecture:** Standard-library Python runtime, generated host manifests and a harmless diagnostic skill. All remote experiments use disposable resources; private evidence stays outside distribution artifacts.

**Spec:** [Design](../specs/2026-09-13-paper2lark-design.md), milestone M0.

## Constraints

- Python >=3.11; English public files; no embedded account identifiers or credentials.
- Resolve launcher files relative to their own location, never the caller's working directory.
- No production library mutations, automatic login, or implicit remote retries.
- Report observed support separately from planned support.

## Tasks

- [x] Write failing subprocess tests for portable packages, Unicode paths, integrity checks and shared state resolution.
- [x] Implement `src/paper2lark`, `scripts/build_plugins.py`, the packaged launcher and canonical diagnostic skill; run tests.
- [x] Validate both generated manifests with installed host tooling and exercise host skill loading.
- [x] Characterize Lark creation, fields, URLs, revisions, assets and native copy in disposable resources; retain private evidence.
- [x] Publish an evidence-based compatibility report and reproducible commands; rerun checks.

## Outcome

Independent review identified output-directory contamination and insufficient URL validation; both were reproduced by failing regression tests and corrected. See [the report](../../compatibility-m0.md) for evidence and the required revision-concurrency fallback. No paper workflows are claimed by this milestone.

## Verification

Run `python -m unittest discover -s tests -v`; build with `python scripts/build_plugins.py`; validate generated plugin manifests. Host and live Lark checks are separate integration gates, never simulated by unit-test success.
